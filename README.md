# Codex CLI Plus

**给 Codex CLI 一个独立的 Windows 入口，把常用会话、并行终端和工作状态放在同一个窗口里。**

如果你每天都在多个 Codex 会话、CMD / PowerShell 窗口和本地服务之间切换，真正打断工作的常常是这些小事：任务栏里分不清窗口、忘了某段会话的 ID、反复拼接恢复命令、来回确认哪个 Agent 还在工作。

Codex CLI Plus 把这些重复操作收进一个轻量的桌面工作台。你继续使用本机的 Codex CLI、账号和会话记录，应用负责让它更容易找到、更方便恢复，也更适合同时处理多个任务。

## 为什么做这个项目

### 从任务栏直接找到 Codex

运行服务的命令行和 Codex 窗口很容易挤在同一组终端图标里。Codex CLI Plus 有独立的应用身份和可自定义图标，让你从任务栏直接定位到自己的 Codex 工作区，减少逐个翻窗口的次数。

### 把会话 ID 变成可以点击的入口

一段有价值的会话不应该每次都靠翻历史记录、复制 ID、重写命令来恢复。

在首页保存会话 ID，软件自动生成：

```powershell
codex --no-daemon resume <会话ID>
```

名称可以自己取，例如“后端重构”“面试准备”；留空时会根据 ID 生成名称。工作目录可留空，恢复时由 Codex 处理已有会话的目录。下次点击“打开”即可恢复，不必重复输入整段命令。

### 并行工作时，知道自己在等什么

多个任务同时进行时，窗口开着不代表 Agent 仍在工作。

应用接收 Codex 的会话状态：工作时显示点阵动画，回复完成或等待输入时停止；需要授权、回答问题或登录时显示相应状态。后台标签也会持续更新，你可以继续做其他事，再切回需要处理的会话。

### 保留熟悉的命令行体验

终端使用 xterm.js 和 Windows ConPTY，通过真实 PowerShell 运行 Codex 和其他命令。支持彩色输出、中文、复制粘贴、中断进程和 Ctrl＋滚轮调整字号。你也可以保存 `npm run dev` 等服务启动命令，让日常开发入口集中在一起。

## 主要功能

- **常用会话首页**：保存、编辑、删除会话入口，多个窗口实时同步配置。
- **填写 ID 即可恢复**：自动拼接 `codex --no-daemon resume <ID>`，显示生成的命令，点击打开时才执行。旧版命令框中直接填写的 ID 也能识别。
- **多标签与独立窗口**：每个终端有独立 PTY、进程、输入与滚动记录。同一个配置可以多次打开；切换标签和返回首页不会结束后台进程。
- **实时工作状态**：优先跟随 Codex 的生命周期信号显示工作、完成和等待状态，避免把“进程仍在运行”误判为“还在回答”。
- **动态会话标题**：跟随 Codex Rename 等标题更新，同步标签、原生窗口和任务栏标题；滤除标题中重复的动画字符。
- **完整颜色与字号支持**：ANSI 16 色、256 色、24 位真彩色、粗体、斜体、下划线；字号 8–48px，自动记忆。
- **自定义应用图标**：默认动漫头像，可在菜单中换成自己的 PNG / ICO 图标。

## 快速使用

### 运行便携版

打开构建产物：

```text
dist/Codex-CLI-Plus-0.3.7.exe
```

应用启动后进入首页，不会自动打开 Codex。运行环境为 Windows 10 / 11，当前在 Windows 11 上验证。

### 添加已有 Codex 会话

1. 点击“添加常用会话”，粘贴会话 ID。
2. 按需填写名称和工作目录，均可留空。
3. 检查自动生成的恢复命令，保存后点击“打开”。

恢复命令使用本机安装的 `codex`，需要当前 Codex CLI 支持所配置的命令参数。应用不会自动安装 Codex 或替你登录。

### 新开终端或启动服务

点击“新建终端”进入普通 PowerShell。添加服务入口时，将会话 ID 留空，填写名称和自定义启动命令；需要固定项目路径时再指定工作目录。

“新窗口”打开另一个首页，常用会话卡片上的“独立窗口”则会在新窗口打开该配置。再次运行 EXE 也可以新开窗口。

### 常用快捷键

- `Ctrl+Shift+T`：新建终端。
- `Ctrl+Shift+N`：新窗口。
- `Ctrl+Shift+H`：返回首页。
- `Ctrl+Shift+W`：关闭当前会话。
- `Ctrl+鼠标滚轮` / `Ctrl+加减号`：调整终端字号；`Ctrl+0` 恢复 14px。
- `Ctrl+Shift+C` / `Ctrl+Shift+V`：复制 / 粘贴。
- `Ctrl+C`：中断当前前台程序。

关闭标签只结束该会话。关闭窗口前会确认是否结束其中的会话，其他窗口不受影响。

## 配置与升级

常用会话和图标设置保存在：

```text
%APPDATA%/codex-cli-plus/settings.json
```

首次以新名称启动时，如果尚无新配置，会从旧版 `%APPDATA%/codex-terminal/settings.json` 复制配置，保留原文件。已有的新配置不会被覆盖。Codex 自身的登录状态和会话内容仍由 Codex CLI 管理。

更换图标会应用到打开的窗口。Windows 已固定的快捷方式可能缓存旧图标，重新固定后可更新。

## 开发与构建

需要 Node.js 22 或更新版本，以及 npm。

```powershell
npm ci
npm start
```

构建 Windows x64 便携版：

```powershell
npm run dist
```

技术结构：Electron 管理窗口和应用身份，xterm.js 显示终端内容，node-pty / ConPTY 连接 PowerShell 与前台程序。会话、输入、输出、标题与状态按窗口和终端 ID 隔离。

## 验证

```powershell
npm run check
npm run smoke
```

检查覆盖会话 ID 命令生成、启动参数传递、配置迁移、多终端隔离、多窗口同步、动态标题、动画去重、颜色与字体缩放，以及终端状态协议解析。

可选的真实 Codex 测试：

```powershell
npm run test:codex
```

该测试使用本机已有登录发起一次短回复，检查真实配色、忙闲变化和回复完成后停止动画，会消耗少量账号额度，不包含在默认检查中。

## 当前边界

- 应用增强的是会话组织和终端交互，不改变 Codex 的模型能力、回答质量、账号额度或执行权限。
- 首页保存的是启动入口。恢复 Codex 对话与恢复终端进程是两回事；应用退出后不会恢复仍在运行的服务或 PowerShell 内存状态。
- 精确的 Codex 忙闲状态依赖其 `OSC 7501` 生命周期信号。其他程序兼容 `OSC 9;4` 进度协议；未报告状态时按 PowerShell 前台命令生命周期判断，交互等待期间可能仍显示“程序运行中”。
- 标题同步依赖前台程序发送终端标题，动态改名不会修改首页保存的配置名称。
- 目前聚焦 Windows 单机使用，尚未提供分屏、远程连接和跨设备同步。

Codex CLI Plus 是独立的桌面配套项目，并非 OpenAI 官方产品。
